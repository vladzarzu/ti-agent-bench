# ti-agent-bench

A benchmark for grading AI agents on threat intelligence tasks.

**Status: design stage.** This repository currently holds the design only.
Tasks, scorers and results will be added as they are built. See the roadmap.

## The idea

An agent is given a task a threat analyst would recognise, such as finding a
persistence mechanism in endpoint telemetry or recovering a command from an
obfuscated script. Its answer is scored against a ground truth that is known
for certain.

## Why this exists

When an agent fails a security task, there are two possible causes. The agent
reasoned badly, or the task was flawed: an ambiguous prompt, a ground truth
that admits other valid answers, a scorer that punishes formatting. A
benchmark that cannot tell these apart measures its own defects.

This project is designed around that distinction.

## Design principles

1. **Ground truth comes from construction or observation.** An obfuscated
   sample is generated from a known command. Telemetry is captured from a lab
   host where the behaviour was reproduced. Ground truth is never the author's
   opinion of what the answer should be.
2. **Scoring is deterministic.** The same answer always gets the same score,
   and every score can be explained field by field. No model grades another
   model.
3. **Every task declares its provenance and its known ambiguities.** A task
   says whether its data is synthetic, lab-captured or from a public report,
   and records where a correct answer could be marked wrong.
4. **Defensible answers are not penalised.** Where analysts would disagree,
   the task lists the alternatives as accepted.

## Planned task families

| Family | The agent is given | The agent returns | Ground truth from |
|---|---|---|---|
| Hunting | Endpoint telemetry | Technique ID and the artifacts involved | Lab capture |
| Mapping | A description of attacker behaviour | MITRE ATT&CK technique IDs | The ATT&CK knowledge base |
| Deobfuscation | An obfuscated script | The hidden command's key elements | The generator that built the sample |

## Data policy

- All task data will be written for this project, generated by code in this
  repository, or taken from public sources. Nothing comes from any employer or
  client environment.
- Samples will be benign: hidden commands point at reserved test domains, and
  sample scripts print their payload instead of running it.

## Roadmap

- [ ] Task file format and validator
- [ ] First task in each family
- [ ] Deterministic scorers with tests
- [ ] Runner that sends tasks to a model and stores the full transcript
- [ ] Ten or more tasks across the three families
- [ ] Results for at least two models
- [ ] Failure review: label each failed task as an agent error or a task flaw,
      and publish the findings
