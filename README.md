# ti-agent-bench

A small benchmark for grading AI agents on threat intelligence tasks.

An agent is given a task a threat analyst would recognise, such as finding a
persistence mechanism in endpoint telemetry or recovering a command from an
obfuscated script. Its answer is scored against a ground truth that is known
for certain.

**Status: early.** Three tasks, two scorers, a task validator and a test
suite. The model runner and the results are not built yet. See the roadmap.

## Why this exists

When an agent fails a security task, there are two possible causes. The agent
reasoned badly, or the task was flawed: an ambiguous prompt, a ground truth
that admits other valid answers, a scorer that punishes formatting. A
benchmark that cannot tell these apart measures its own defects.

This project is built around that distinction.

## Design principles

1. **Ground truth comes from construction or observation.** An obfuscated
   sample is generated from a known command. Telemetry is captured from a lab
   host where the behaviour was reproduced. Ground truth is never the author's
   opinion of what the answer should be.
2. **Scoring is deterministic.** The same answer always gets the same score,
   and every score can be explained field by field. No model grades another
   model.
3. **Every task declares its provenance and its known ambiguities.** A task
   says whether its data is synthetic, lab-captured or from a public report,
   and its notes record where a correct answer could be marked wrong.
4. **Defensible answers are not penalised.** Where analysts would disagree,
   the task lists the alternatives as accepted.

## Task families

| Family | The agent is given | The agent returns | Ground truth from |
|---|---|---|---|
| Hunting | Endpoint telemetry (JSON lines) | Technique ID and the artifacts involved | Lab capture, or synthetic events marked as such |
| Mapping | A description of attacker behaviour | MITRE ATT&CK technique IDs | The ATT&CK knowledge base |
| Deobfuscation | An obfuscated script | The hidden command's key elements | The generator that built the sample |

Current tasks:

| ID | Family | Provenance | Title |
|---|---|---|---|
| `hunt-001` | hunting | synthetic | Find the persistence mechanism in Linux endpoint telemetry |
| `map-001` | mapping | synthetic | Map an intrusion narrative to ATT&CK techniques |
| `deob-001` | deobfuscation | synthetic | Recover the command hidden in a layered PowerShell script |

## Quick start

Requires Python 3.10 or later.

```bash
git clone https://github.com/<your-username>/ti-agent-bench.git
cd ti-agent-bench
python -m venv .venv && source .venv/bin/activate
pip install -e .

tibench list                 # show all tasks
tibench validate             # check every task definition
python -m unittest discover -s tests -v
```

Score an answer file:

```bash
tibench score examples/answers/map-001.partial.json
```

```json
{
  "task_id": "map-001",
  "score": 0.5714,
  "passed": false,
  "details": {
    "precision": 0.6666666666666666,
    "recall": 0.5,
    "true_positives": ["T1059.001", "T1566.001"],
    "false_positives": ["T1547.001"],
    "missed": ["T1003.001", "T1053.005"],
    "accepted_extras": ["T1204.002"]
  }
}
```

## How scoring works

Each task names one scoring method in its `task.yaml`.

**`exact_fields`** is for answers made of named fields. The score is the
fraction of fields that match the ground truth. Matching ignores case and
surrounding whitespace, except for fields the task lists as `case_sensitive`,
such as Linux file paths.

**`technique_set`** is for lists of ATT&CK technique IDs. The score is F1
over the `required` techniques. Techniques in the task's `accepted` list are
neither rewarded nor penalised. Anything else counts as a false positive.

A malformed answer scores 0.0 and never raises an error, so one bad response
cannot stop a run.

The task file format is described in [docs/TASK_FORMAT.md](docs/TASK_FORMAT.md).

## Data policy

- All task data is written for this project, generated by code in this
  repository, or taken from public sources. Nothing comes from any employer or
  client environment.
- Samples are benign. Hidden commands point at reserved test domains and
  documentation IP ranges, and sample scripts print their payload instead of
  running it.
